# 課題解決プロンプト: zustandのset内副作用とUndo履歴の不整合を修正する

## 1. 役割定義 (Persona)
あなたはzustandと状態管理パターンに精通したエンジニアです。副作用の適切な分離とUndo履歴の一貫性を確保してください。

## 2. 背景・前提条件 (Context)

### 問題A: `updateNodeParent` で `set` の中から `pushSnapshot` を呼んでいる
- **ファイル**: `src/store/useStore.ts`
- **該当箇所**: `updateNodeParent` アクション
```ts
updateNodeParent: (nodeId, newParentId) => {
    set((state) => {
      // 早期リターン判定（同一親、循環参照チェックなど）
      if (nodeId === ROOT_NODE_ID || nodeId === newParentId) return state;
      // ...
      if (collectDescendants(nodeId, state.edges).has(newParentId)) return state;

      // ← ここまで早期リターンすると pushSnapshot は呼ばれない
      useHistoryStore.getState().pushSnapshot(); // ← setの中で副作用！
      return { nodes: ..., edges: ... };
    });
    get().applyAutoLayout(); // ← setの後にも副作用
},
```
- **問題**: `set` コールバックは純粋関数であるべき。早期リターン時は `pushSnapshot` が呼ばれず、Undo履歴と実際の状態に不整合が生じる

### 問題B: `pushSnapshot` の呼び出しが操作によって一貫していない
- `addNode` / `addChildNode` / `addSiblingNode` / `removeNode` / `updateNodeLabel` / `importGraph` / `resetGraph`: **履歴を取る**
- `onNodesChange`（ドラッグ）/ `onEdgesChange` / `onConnect`: **履歴を取らない**
- `updateNodeParent`: **条件付きで履歴を取る**
- **結果**: ノードをドラッグしてからUndoすると、ドラッグ前ではなく遥か昔の状態に戻ってしまう

### 関連ファイル
- `src/store/useStore.ts`
- `src/store/useHistoryStore.ts`

## 3. 解決すべきゴール (Goal & Objective)
- [ ] `updateNodeParent` の副作用を `set` の外に移動する（早期リターンは事前に `get()` で判定し、更新が確定した場合のみ `set` + `pushSnapshot` + `applyAutoLayout` を行う）
- [ ] `onNodesChange`（ドラッグ操作）に対して適切な履歴管理を行う。ドラッグ中は履歴を取らず、ドラッグ終了時（`onNodeDragStop` 既存）に1回だけ履歴を取る方式を検討する
- [ ] 全操作で `pushSnapshot` の呼び出しパターンを統一する（操作前/操作後どちらに統一するか決める）
- [ ] Undo/Redo後の状態でさらに操作した場合、Redoスタックが正しくクリアされることを確認する（既存コードでは `pushSnapshot` 時に `redoStack: []` しているので正しいはず）

## 4. 期待する成果物 (Output Format)
- 修正後の `src/store/useStore.ts`
- Undo/Redoの動作を検証する追加テストケース
- `npx vitest run` の全件パス結果

## 5. 実行開始の合図
このプロンプトを理解したら、「タスクを開始します」と宣言し、直ちに `useStore.ts` の全 `pushSnapshot` 呼び出し箇所の洗い出しから始めてください。
