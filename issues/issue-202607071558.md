# 課題解決プロンプト: useHistoryStore（Undo/Redo）のユニットテストを追加する

## 1. 役割定義 (Persona)
あなたは状態管理とテストに精通したソフトウェアエンジニアです。アプリの中核機能であるUndo/Redo機構に対し、すべての状態遷移をカバーするユニットテストを追加してください。

## 2. 背景・前提条件 (Context)

### 現状
- **ファイル**: `src/store/useHistoryStore.ts`
- **テスト**: **ゼロ**（間接的に `useStore.test.ts` から操作されるのみ。`pushSnapshot`, `undo`, `redo` の単体での動作確認は一切なし）
- **影響**: Undo/Redoはユーザー操作の取り消しに関わる中核機能だが、バグがあっても検出されない

### useHistoryStore のインターフェース
```ts
pushSnapshot()   // 現在の状態を undoStack に積み、redoStack をクリア
undo()           // undoStack の最新を復元し、現在の状態を redoStack に積む
redo()           // redoStack の最新を復元し、現在の状態を undoStack に積む
clearHistory()   // 両スタックをクリア（現在未使用のデッドコード）
canUndo()        // undoStack が空でないか
canRedo()        // redoStack が空でないか
maxHistory: 50   // 履歴の上限
```

### テストすべきケース

| # | ケース | 検証内容 |
|---|-------|---------|
| 1 | pushSnapshot 基本 | undoStack の長さが1増え、redoStack が空になる |
| 2 | pushSnapshot 連続 | 複数回pushで undoStack に順次積まれる |
| 3 | undo 基本 | 状態が1つ前に戻り、現在の状態が redoStack に入る |
| 4 | redo 基本 | 状態が1つ先に進み、現在の状態が undoStack に戻る |
| 5 | 空undoStackでundo | 何も起こらずエラーにもならない |
| 6 | 空redoStackでredo | 何も起こらずエラーにもならない |
| 7 | pushSnapshotがredoStackをクリア | undo → pushSnapshot → redoStackが空になっている（分岐履歴の破棄） |
| 8 | maxHistory超過 | 51回push → undoStackの長さが50で、最古の履歴が捨てられている |
| 9 | canUndo / canRedo | 初期状態でfalse、push後canUndoがtrue、undo後canRedoがtrue |
| 10 | 完全なundo→redo→undoサイクル | 元の状態に戻ること |

### テストの設計方針
- `useHistoryStore` は `useStore` に依存している（`getCurrentSnapshot` が `useStore.getState()` を呼ぶ）
- テストでは `useStore.setState()` を使って任意の状態を作り、`useHistoryStore` の各メソッドを検証する
- vitest の `beforeEach` で `useStore` と `useHistoryStore` の状態をリセットする
