# 課題解決プロンプト: MindMapNodeコンポーネントのユニットテストを追加する

## 1. 役割定義 (Persona)
あなたは React Testing Library に習熟したフロントエンドエンジニアです。アプリ内で最もロジックの濃いUIコンポーネント `MindMapNode` に対し、インタラクション中心のコンポーネントテストを追加してください。

## 2. 背景・前提条件 (Context)

### 現状
- **ファイル**: `src/nodes/MindMapNode.tsx`
- **テスト**: **ゼロ**
- **コンポーネントの責務**:
  - ノードの表示（ラベル表示 / 編集モード切替）
  - キーボード入力による編集モード開始（Space, 文字キー）
  - ダブルクリックによる編集モード開始
  - インライン編集（Input） → フォーカス喪失で確定
  - 編集モード中のキーボードショートカット（Tab→子追加, Enter→兄弟追加, Backspace/Delete空欄→削除）
  - Handle（ReactFlowの接続ポイント）の描画

### テスト環境
- vitest + React Testing Library
- 現在 `vite.config.ts` の `test.include` は `src/**/*.test.ts` のため、`.test.tsx` もカバーされるよう `src/**/*.test.{ts,tsx}` に変更が必要な可能性がある
- `@xyflow/react` の `Handle` コンポーネントや `useStore` 依存のモックが必要

### テストすべきケース

| # | ケース | 検証内容 |
|---|-------|---------|
| 1 | 通常表示 | ラベルが表示され、input が表示されていない |
| 2 | 空ラベルでマウント | 自動的に編集モード（input表示）になる |
| 3 | ダブルクリック | 編集モードに切り替わり、input にフォーカス |
| 4 | Spaceキー | 編集モードに切り替わる |
| 5 | 文字キー押下 | 編集モードに入り、その文字が draftLabel に入る |
| 6 | Tab（編集モード中） | ラベル確定 + addChildNode 呼び出し |
| 7 | Enter（編集モード中） | ラベル確定 + addSiblingNode 呼び出し |
| 8 | Backspace（空欄・編集モード中） | removeNode 呼び出し |
| 9 | input の blur | ラベル確定（commitLabel） → 編集モード終了 |
| 10 | 選択状態のスタイル | selected prop が true のとき border-primary クラスが付与される |

### 考慮事項
- `useStore` のモック: zustand のストアはテスト内で `useStore.setState()` を使って直接操作可能
- `Handle` コンポーネント: `@xyflow/react` をモックするか、ReactFlowProvider でラップする
- `fitView` などの ReactFlow フック: モックが必要な可能性がある

### 関連ファイル
- `src/nodes/MindMapNode.tsx`
- `src/store/useStore.ts`
- `vite.config.ts`

## 3. 解決すべきゴール (Goal & Objective)
- [ ] `src/nodes/MindMapNode.test.tsx` を新規作成し、上記8〜10ケースを実装する
- [ ] テスト実行に必要なモック設定を行う（zustandストア、ReactFlow）
- [ ] `npx vitest run` で全件パスすることを確認する
- [ ] 必要に応じて `vite.config.ts` の `test.include` を `src/**/*.test.{ts,tsx}` に拡張する

## 4. 期待する成果物 (Output Format)

- 必要に応じた `vite.config.ts` の修正
- `npx vitest run` の実行結果（全件パス）
