## 2. 背景・前提条件 (Context)

### 現状
以下の2ファイルにはテストが一切存在しません。いずれも**純粋関数**であり、テストのコストが極めて低く、効果が極めて高い状態です。

### 対象A: `src/utils/orgModeTags.ts`
```ts
getOrgModeSideTag(label)    // 文字列末尾の :LEFT: / :RIGHT: タグを抽出
stripOrgModeSideTag(label)  // タグを除去してトリム
appendOrgModeSideTag(label, sideTag) // ラベル末尾にタグを付与
```

**テストすべき最低限のケース:**
- `getOrgModeSideTag`: タグあり（LEFT/RIGHT）、タグなし、空文字列、タグが文中にある、`:LEFT:` のみの文字列
- `stripOrgModeSideTag`: タグあり除去、タグなしで変化しない、前後の空白トリム、`:LEFT:` のみ→空文字列
- `appendOrgModeSideTag`: LEFT付与、RIGHT付与、空ラベルに付与、既にタグありのラベルに付与（二重タグ）

### 対象B: `src/utils/edgeHandles.ts`
```ts
createDirectionalEdge(sourceNode, targetNode)   // 方向付きエッジ生成
rebuildDirectionalEdges(nodes, edges)            // 全エッジの方向再計算
// 内部: getDirectionalEdgeHandles(source, target)
```

**テストすべき最低限のケース:**
- `createDirectionalEdge`:
  - ターゲットがソースより左（target.position.x < source.position.x）→ `LEFT_SOURCE_HANDLE_ID` + `RIGHT_TARGET_HANDLE_ID`
  - ターゲットがソースより右 → `RIGHT_SOURCE_HANDLE_ID` + `LEFT_TARGET_HANDLE_ID`
  - 同一X座標 → 右側扱いになること（現在の実装のデフォルト挙動確認）
  - 生成されるエッジIDが `sourceId-targetId` 形式であること
- `rebuildDirectionalEdges`:
  - 正常系：全エッジのhandleが再計算される
  - 存在しないノードIDを含むエッジ → 元のエッジがそのまま返る（破壊しない）
