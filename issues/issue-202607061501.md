# 課題解決プロンプト: MindMapNodeのuseEffect依存配列バグ

## 1. 役割定義 (Persona)
あなたはReactのベストプラクティスに精通したフロントエンドエンジニアです。`useEffect` の依存配列の誤りを修正し、ノード選択時のフォーカス制御を正しく動作させてください。

## 2. 背景・前提条件 (Context)

### 問題: 空依存配列のuseEffectが外部変数に依存している
- **ファイル**: `src/nodes/MindMapNode.tsx`
- **該当箇所**:
```tsx
useEffect(() => {
    if (selected && !isEditing && data.label !== '') {
      globalThis.requestAnimationFrame(() => {
        globalThis.requestAnimationFrame(() => {
          buttonRef.current?.focus();
        });
      });
    }
  }, []); // ← 空配列だが、selected, isEditing, data.label に依存している
```
- **現状の動作**: マウント時の1回しか実行されず、後から `selected` や `isEditing` が変わっても反応しない
- **期待される動作**: `selected` が `true` になったときや、編集モードが解除されたときに適切にフォーカスを当てる
- **備考**: 同じファイル内に別の `useEffect` で `wasSelectedRef` を使ったフォーカス制御があるため、この空依存配列の `useEffect` と重複している可能性がある

### 関連するuseEffect群（同ファイル内）:
1. `[data.label, isEditing]` - ラベル同期（これは正しい）
2. `[isEditing]` - 編集モード時のinputフォーカス（正しい）
3. `[isEditing]` - 編集終了時のボタンフォーカス戻し（正しい）
4. `[]`（問題の箇所） - 初回選択時フォーカス → **依存配列が誤り**
5. `[isEditing, selected]` - 選択変更時のフォーカス（正しい）
6. `[data.label]` - 初回空ラベル時の編集モード開始（意図的に初回のみだが依存配列が誤解を招く）

### 関連ファイル
- `src/nodes/MindMapNode.tsx`

## 3. 解決すべきゴール (Goal & Objective)
- [ ] 問題の `useEffect`（依存配列が `[]`）の意図を明確にし、正しい依存配列に修正する
- [ ] 他の `useEffect` との重複がないか確認し、必要に応じて統合する
- [ ] `[data.label]` 依存の `useEffect`（初回限定だが `didInitializeRef` でガード）も、意図が明確になるようリファクタする（依存配列を `[]` にするか、コメントを追加）
- [ ] 修正後、ノード選択→フォーカス、ダブルクリック→編集、Spaceキー→編集 の一連の操作が正しく動作することを確認
