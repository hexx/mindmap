# 課題解決プロンプト: E2Eテストを1本のスモークテストに削減し、コンポーネントテストに置き換える

## 1. 役割定義 (Persona)
あなたはテスト戦略に精通したソフトウェアエンジニアです。テストピラミッドの原則に従い、過剰なE2Eテストを排除し、適切なレイヤーにテストを再配置してください。

## 2. 背景・前提条件 (Context)

### 現状
- **ファイル**: `tests/mindmap.spec.ts`
- **内容**: 12個のPlaywright E2Eテスト
- **問題点**:
  1. 使用しているCSSクラスセレクタ（`.main-menu__dropdown`, `.mindmap-node--selected`, `.mobile-toolbar` など）が実装コンポーネントに**一切存在しない**ため、12件全滅している
  2. テスト対象がE2Eに不適切な粒度 — コンポーネントレベルの挙動（編集モード切替、キーボードショートカット、CSSプロパティ検証、PWAメタタグ確認）をブラウザ経由でテストしている
  3. shadcn/uiの内部動作（DropdownMenuの開閉）を自前でテストしており、ライブラリの責務と混同している
  4. 実行が遅く（ブラウザ起動＋Viteビルド）、壊れやすく（CSSクラス名の変更で全滅）、偽の安心感を与えている

### テストピラミッドの原則
- E2Eは「アプリ全体が繋がって動くこと」の確認に留め、本数は最小限に
- コンポーネントの個別の振る舞いは React Testing Library + vitest で高速にテストする
- CSSプロパティやメタタグの検証は、より軽量な方法で行う

### 現在のE2Eテストの内訳と移行先

| 現E2Eテスト | 判定 | 移行先 |
|------------|:--:|------|
| ルートノードが表示されている | ✅ スモークテストに残す | E2E |
| Tabで子ノード追加＋フォーカス | 🔄 スモークテストに統合 | E2E |
| Enterで兄弟ノード追加＋フォーカス | ❌ | コンポーネントテスト |
| PWA icon/manifest確認 | ❌ | `index.html` の静的チェック（もしくは不要） |
| 起動直後のフォーカス | ❌ | コンポーネントテスト |
| 新規作成後のフォーカス | ❌ | コンポーネントテスト |
| メニュー6アクション縦並び | ❌ | 削除（CSS検証はE2Eの責務でない） |
| メニュー外クリックで閉じる | ❌ | 削除（shadcn/uiの動作。自前コードのテストではない） |
| ダブルクリックで編集モード | ❌ | コンポーネントテスト |
| Spaceで編集モード | ❌ | コンポーネントテスト |
| モバイルツールバー操作 | ❌ | コンポーネントテスト |
| 文字キーで編集モード | ❌ | コンポーネントテスト |
| Delete/Backspaceで削除 | ❌ | コンポーネントテスト |
| 矢印キーでフォーカス移動 | ❌ | コンポーネントテスト |

### 関連ファイル
- `tests/mindmap.spec.ts`（削除対象）
- `tests/smoke.spec.ts`（新規作成）
- `playwright.config.ts`

## 3. 解決すべきゴール (Goal & Objective)
- [ ] `tests/mindmap.spec.ts` を削除する
- [ ] `tests/smoke.spec.ts` を新規作成し、以下の**1本のスモークテスト**のみを含める:
  ```ts
  test('アプリが起動し、基本的なノード操作ができる', async ({ page }) => {
    await page.goto('/');
    // React + ReactFlow + Store の結合確認
    await expect(page.getByRole('button', { name: 'ルート（中心概念）' })).toBeVisible();
    // キーボードショートカット + Store + ReactFlow の結合確認
    await page.getByRole('button', { name: 'ルート（中心概念）' }).press('Tab');
    await expect(page.getByPlaceholder('ラベルを入力')).toBeVisible();
  });
  ```
- [ ] 削除したテストのうち価値のある検証は、**別issue**で対応するコンポーネントテストに移行する（この issue の範囲外）
- [ ] `npx playwright test` がパスすることを確認する
- [ ] CIでのE2E実行時間が大幅に短縮されることを確認する

## 4. 期待する成果物 (Output Format)
- 削除: `tests/mindmap.spec.ts`
- 新規: `tests/smoke.spec.ts`
- `npx playwright test` の実行結果（1 test passed, 所要時間○秒）

## 5. 実行開始の合図
このプロンプトを理解したら、「タスクを開始します」と宣言し、直ちに `tests/mindmap.spec.ts` の削除から始めてください。
