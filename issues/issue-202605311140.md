npx wrangler dev で起動したところ、`POST /api/mindmaps` へのリクエストが `404 Not Found` になり、`favicon.ico` が `500 Internal Server Error` になる不具合が発生しています。
原因は、バックエンドのAPI処理が Workers のエントリーポイントとして正しく認識されていない（または静的アセットの配信と競合している）ためです。以下の要件を満たすように構成を修正してください。

【要件1: Workerエントリーポイントの作成とルーティング】
1. `src/worker.ts` （または `server.ts`）を新規作成し、`export default { async fetch(request, env) { ... } }` の形式で Workers のメイン処理を記述してください。
2. リクエストURLのパスを解析し、`/api/mindmaps` や `/api/mindmap/:id` などの API 宛てのリクエストの場合は、作成したD1の処理（GET/POST/DELETEなど）を実行して JSON を返すようにルーティングしてください。
3. **重要**: パスが `/api/` で始まらないその他のリクエスト（Reactの画面や `favicon.ico` などの静的ファイル）については、Cloudflare の新しい静的アセット機能に従ってそのままアセットを返す処理（必要に応じてフォールバック）を実装してください。

【要件2: wrangler.toml の修正】
1. 現在の `wrangler.toml` に `main = "src/worker.ts"` （要件1で作成したファイルへのパス）を追記し、このファイルが Workers の入り口として実行されるようにしてください。

【要件3: エンドポイント名の統一チェック】
1. フロントエンド（`useStore.ts`）がリクエストしているURLと、バックエンド（`worker.ts`）で受け付けるURLが、単数形（mindmap）か複数形（mindmaps）で食い違っていないか確認し、一致するようにコードを修正してください。
