# 課題解決プロンプト: useStoreの責務過多を解消し、ストアを分割する

## 1. 役割定義 (Persona)
あなたはzustandを用いた状態管理の専門家です。単一責任の原則（SRP）に従い、420行の巨大なストアを適切な単位に分割してください。

## 2. 背景・前提条件 (Context)

### 現状
- **ファイル**: `src/store/useStore.ts`（約420行）
- **含まれる責務**:
  1. ノード・エッジのCRUD操作
  2. Undo履歴（`useHistoryStore`）との連携
  3. クラウドAPI通信（fetch/save/load/delete）
  4. d3-hierarchy を用いた自動レイアウト計算
  5. キーボードフォーカス移動ロジック
  6. インポート/エクスポート用の状態初期化
  7. localStorage永続化（zustand persist）

### 問題点
- 単一のストアがアプリケーションのほぼ全てのロジックを抱えており、変更の影響範囲が読めない
- テストが書きづらい（モックすべき対象が多い）
- 各操作がストア内部で密結合している

### 提案する分割案
```
src/store/
  useGraphStore.ts    # ノード・エッジの純粋な状態操作（add, remove, update, connect）
  useCloudStore.ts    # クラウド保存/読込/削除/一覧取得
  useLayoutStore.ts   # 自動レイアウト計算（d3-hierarchy）
  useHistoryStore.ts  # 既存（Undo/Redo）
```
`useStore` はこれらを束ねるファサードとして残すか、各コンポーネントが直接必要なストアを参照する形に移行する。

### 関連ファイル
- `src/store/useStore.ts`
- `src/store/useHistoryStore.ts`
- `src/App.tsx`
- `src/nodes/MindMapNode.tsx`
- `src/components/MobileToolbar.tsx`
- `src/components/SavedMindmapsModal.tsx`
- `src/store/useStore.test.ts`

## 3. 解決すべきゴール (Goal & Objective)
- [ ] `useStore` を責務ごとに3〜4個の独立したストアに分割する
- [ ] 分割後も既存のコンポーネントが動作するよう、インポートパスとセレクタを修正する
- [ ] `useHistoryStore.pushSnapshot()` の呼び出し元を適切に整理する（現状、一部の操作でのみ呼ばれている問題も合わせて解決）
- [ ] 既存のテストを分割後のストア構成に合わせて修正する
- [ ] 後方互換性のために `useStore` をファサードとして残すか検討する

## 4. 期待する成果物 (Output Format)
- 新設した各ストアファイル
- 修正後の既存ファイル（App.tsx, MindMapNode.tsx 他）
- `npx vitest run` の全件パス結果
- 分割方針の説明コメント

## 5. 実行開始の合図
このプロンプトを理解したら、「タスクを開始します」と宣言し、直ちに `useStore.ts` の全アクションの分類から始めてください。
